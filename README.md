# 右键助手 · macOS 日常使用测试版

原生 Swift macOS Finder 右键工具，当前版本 **0.6.0（build 18）**。主应用使用 AppKit 管理窗口与生命周期，SwiftUI 提供设置界面，Finder Sync 扩展提供右键入口。

- 新建 Word、PowerPoint、Excel、TXT、Markdown、JSON，自动处理同名文件。
- 复制完整路径、文件名或终端转义路径；打开 Terminal 与常用应用。
- 自定义菜单、目录授权、首次使用引导和诊断。
- 双击左 Shift 打开文本剪贴板历史，可选自动粘贴。
- 登录后后台启动，并提供 macOS 服务入口。


本轮开机启动与稳定性结果见 [M3 检查记录](./docs/M3-STABILITY-REPORT.md)，文本历史见 [文本历史移植报告](./docs/CLIPBOARD-REPORT.md)；此前功能见 [M2 验收报告](./docs/M2-REPORT.md) 和 [菜单覆盖修复报告](./docs/MENU-COVERAGE-REPORT.md)。干净账户、系统重启、跨 macOS 版本和发行公证仍按 [安装测试矩阵](./docs/INSTALL-TEST-MATRIX.md) 留到 M3。

0.5.2 的新建窗口与图标修复见 [新建窗口验收记录](./docs/ACTION-DIALOG-REPORT.md)。

0.5.1 的窗口激活修复与验收见 [窗口修复记录](./docs/CLIPBOARD-FOCUS-REPORT.md)。双 Shift 只显示紧凑历史面板，设置窗口保持原有显示状态。

本机已实测 macOS 26.5.2 / Apple Silicon。最低编译目标为 macOS 14，不代表已验证所有 14 及以上系统。当前使用 Apple Development 签名，**尚未公证，不是公开发行包**。

## 立即试用

默认安装位置：`~/Applications/RightClickHelper.app`。

1. 打开“右键助手”，点击“打开扩展设置”，启用 `RightClickHelper`。
2. 默认勾选“在桌面和所有 Finder 文件夹显示菜单”，不再需要先添加目录才能看到入口。
3. 在普通文件夹空白处右键 → “右键助手” → “新建文件”。首次操作时选择当前目标目录授权，然后输入文件名；后续直接新建。
4. 右键单个文件或多选文件 → “右键助手” → “复制完整路径”。

本机实测系统会把该扩展开关列在“通用 → 登录项与扩展 → 文件提供程序”中，名称是 `RightClickHelper`，不是“访达”快速操作分类。优先通过应用按钮打开系统对应界面，不依赖跨版本固定路径。

菜单显示范围和文件访问权限独立：全 Finder 覆盖只注册菜单，不授予整个磁盘读写权限，也不递归扫描。复制路径无需目录书签；新建文件、打开终端或常用应用首次需要授权当前文件夹。取消授权不会执行操作，也不会阻塞下一次请求。

“工作目录”页可关闭全 Finder 覆盖，恢复为仅已授权目录显示，也可添加或移除目录授权。M2 的专用测试文件位于 `build/POCFixtures/工作目录/M2验收`；你的既有目录授权和常用应用列表会保留。

## M2 设置与使用引导

- **菜单设置**：六类动作开关，选中一行后上移/下移，六种新建格式开关。下次打开 Finder 菜单生效；“打开右键助手”始终保留。
- **常用应用**：可指定默认应用，它在适用的菜单中优先显示，并在服务选择框中预选；不修改系统默认打开方式。
- **恢复默认菜单**：只重置菜单动作、顺序、模板选择及默认应用；保留目录授权、常用应用列表和覆盖范围。
- **使用引导**：选择一个测试文件夹，实际打开右键菜单、复制路径、新建文件后，才允许完成。每次重新测试使用独立记录，不把此前操作或主应用内新建当作 Finder 验证。
- **诊断**：区分扩展启用、菜单覆盖、目录授权和实际操作结果。损坏的共享菜单配置会先备份，再恢复默认，提示用户；私有目录和应用授权保留。

M3 本机稳定性与开机启动验收状态见 [M3 检查记录](./docs/M3-STABILITY-REPORT.md)，区分已通过与待安排项目。

## 开机启动

在“通用”页开启“开机启动（登录后运行）”。通过 macOS 的 `SMAppService.mainApp` 注册当前应用，状态直接读取系统登录项；关闭后取消注册，仍可继续使用当前应用。系统禁用时不会在后台自行重新开启，可通过“系统登录项设置…”处理。

登录启动按后台运行设计，不主动打开设置窗口；正常手动打开仍显示设置。文本历史的启用状态保留，内容仍只存内存，退出和重启后清空。实际注销/重启验收需在可中断工作的时机进行。

## 文本历史与双击左 Shift

1. 在“剪贴板”页勾选“启用文本历史”。首次使用默认关闭；开启后，菜单栏也会出现与 Finder 右键助手相同的点击指针图标。
2. 按页面提示检查剪贴板读取及“隐私与安全性 → 输入监控”权限，允许 `RightClickHelper.app`。系统要求退出重开时照提示操作；返回后点击“刷新权限状态”。较新系统若询问后台读取剪贴板，需选择始终允许。当前系统若已允许读取，无需再弹授权框。
3. 复制文字后，在原应用中快速按下并松开左 Shift 两次。右 Shift、长按及 Shift 组合键不触发；两次按下之间的松开间隔最多 0.3 秒，单次按住最多 0.25 秒。
4. 双 Shift 面板沿用原工具的无边框卡片外观：宽 180 点，按条数增高至最多 291 点；紧贴鼠标下方 12 点，底部空间不够时翻到上方。支持悬停放大、点击或 Enter 选用、Esc/点外部关闭，没有记录时不弹出。默认选择后复制到系统剪贴板并返回原应用，再按 ⌘V 粘贴。搜索、删除和清空放在“剪贴板 → 搜索与管理…”的独立界面。
5. 如需自动粘贴，勾选“自动粘贴回原应用（可选）”，并在系统“隐私与安全性 → 辅助功能”允许已安装的 `RightClickHelper.app`。若列表没有它，点击 `+`，选择 `~/Applications/RightClickHelper.app`。仅在选择历史时发送 ⌘V；权限不足时仍可复制。

最多保存 100 条文本，重复内容移到最前；单条上限 256 KiB，总文本上限 4 MiB。历史只存在主应用内存，退出或停用即清空，不写磁盘、共享容器或日志，也不上传。支持暂停记录、删除单条和清空；暂停期间及启用前的剪贴板内容不会回补。敏感/临时内容只有被来源应用标记时才能识别排除，不能保证识别所有密码或秘密文本。

关闭设置窗口后继续运行；⌘Q 退出后不会记录或响应 Shift，需重新打开应用。开机自启在“通用”页设置；暂不提供图片/文件历史、跨设备同步或跨重启保存。自动粘贴要求原应用仍运行并已回到前台、剪贴板没有被新复制覆盖、修饰键已松开；超时或条件变化只保留复制结果。目标应用是否接受 ⌘V 由其自身决定；终端、远程桌面和特殊编辑器应先关闭自动粘贴试用。

移植参考 `RightButtonExtension` 的 MIT 授权实现，保留 [第三方许可](./ThirdPartyNotices.txt)。如旧工具也监听 Shift，请关闭旧工具的监听，避免两个面板同时出现。

## macOS 服务补充入口

在 Finder 中选中文件或文件夹，再打开 **访达 → 服务 → 右键助手：…**。其他宿主只有在支持传递文件 URL 时才适用；不承诺网页或任意文本区域都有入口。

| 服务 | 输入与行为 |
| --- | --- |
| 复制完整路径 | 一个或多个文件/文件夹，逐行输出 |
| 新建文件… | 单个普通文件夹；选择格式，再输入文件名 |
| 在此打开终端 | 单个普通文件或文件夹；文件使用父目录 |
| 用常用应用打开… | 单个普通文件或文件夹；按目录能力过滤，预选默认应用 |

这些入口不依赖 Finder 扩展启用，但由主应用提供，退出后会自动启动。新建和打开动作复用已有授权及串行请求流程；取消不会阻塞后续操作。有对话框正在处理时，新的交互式服务会提示稍后重试。菜单动作开关仅影响 Finder；新建格式选择同时影响服务。

若服务未出现，到应用“诊断”页点击“刷新服务注册”，再检查系统“键盘 → 键盘快捷键 → 服务”。不要复制或运行安装备份中的应用。开发时可用 `swiftc scripts/service-probe.swift -o build/service-probe` 编译真实系统服务测试客户端，再以动作标识和测试路径调用；它会触发真实操作，须使用测试目录。

## 构建与安装

需要完整 Xcode、Command Line Tools 和本机有效的 Apple Development 签名身份。

```bash
cd RightClickHelper
bash scripts/configure-signing.sh
bash scripts/build.sh
swift test
bash scripts/test-crash-recovery.sh
bash scripts/install.sh
```

`configure-signing.sh` 从本机开发证书提取 Team ID，写入不纳入 Git 的 `Config/Local.xcconfig`，不导出私钥。如有多个开发团队，可指定：

```bash
SIGNING_TEAM=YOURTEAMID bash scripts/configure-signing.sh
```

也可以打开 [Xcode 工程](./RightClickHelper.xcodeproj)，选择 `RightClickHelper` scheme 编译。项目不依赖 Homebrew、第三方 Swift 包或 XcodeGen。[工程生成脚本](./scripts/generate_project.py) 用于添加源文件后重建项目清单；重新运行会覆盖工程、Info.plist 和 entitlement 配置，手工修改这些文件时先同步生成器。

## 更新安装

1. 在系统设置中停用 `RightClickHelper` Finder 扩展。
2. 使用应用菜单或 ⌘Q 退出主应用；仅关闭窗口不会退出进程。
3. 重新构建并运行安装脚本。
4. 重新启用扩展。目录配置和安全作用域书签保留。

0.2.1 修复了 0.2.0 连续更新后创建对话框不可见的问题：请求改为由持久待办目录驱动，异步串行处理，创建表单附着在唯一主窗口上。已通过连续三轮覆盖安装（一次升级、两次同版本重装）、冷启动、连续六次 Office 创建、取消/错误后继续及关闭主窗口后新建验证，详见 [生命周期修复报告](./docs/LIFECYCLE-REPORT.md)。此处描述 0.2.1 的历史修复；当前 0.5.2 及以后已使用独立小窗口。正常更新无需额外重启主应用或 Finder。

安装脚本默认安装到当前用户的 `~/Applications`，无需管理员权限；同名位置属于其他应用时拒绝覆盖。停用扩展和退出主应用后，脚本最多等待 15 秒让旧进程结束；仍在运行就退出，不替换文件。新应用先复制到临时目录并验证完整签名，再替换旧版本；旧副本保留在 `build/InstallBackups`，并取消旧副本与构建副本的注册。失败回滚分支已实现；本轮验证了无效安装包/进程仍运行的拒绝路径，未进行磁盘故障注入。

不要在扩展仍运行时直接覆盖 `.app`；Finder 可能继续使用旧进程。原型不强制重启 Finder，以免影响用户的其他窗口和操作。

## Office 新建文件

在普通目录空白处或单个文件夹上右键 → **右键助手 → 新建文件**，选择 Word、PowerPoint 或 Excel，输入文件名即可。创建后在 Finder 中选中结果，双击可用关联的办公软件编辑。

| 类型 | 初始内容 |
| --- | --- |
| Word `.docx` | 空白文档，一个空段落；现代兼容设置 |
| PowerPoint `.pptx` | 一张 16:9 空白幻灯片，没有标题占位框 |
| Excel `.xlsx` | 一个空白工作表“工作表1” |

三种格式使用随应用签名打包的真正 OOXML 模板，不含宏、外部链接或用户作者信息。创建动作不依赖 Office、Python 或网络。支持自动补扩展名（含已输入的大写扩展名）和同名自动编号；模板缺失时先报错，不留下空的 Office 文件。暂不提供旧 `.doc/.ppt/.xls` 格式、宏模板、自定义模板导入或 PDF 新建。

模板已保存在 `Shared/Resources/`，正常编译不需要重新生成。修改模板时使用 `scripts/generate_office_templates.py`，再运行 `scripts/verify_office_templates.py`；开发依赖是 python-docx 1.2.0、python-pptx 1.0.2、openpyxl 3.1.5 及其 lxml 依赖。校验器检查 ZIP、XML、命名空间、内部引用、空白内容与宏/外部链接，也可传入 Finder 实际生成的文件路径。发布前仍应通过目标 Office 版本实际打开测试。

## 终端与常用应用

- **在此打开终端**：普通目录空白处和单选文件夹打开该目录；单选普通文件打开父目录。多选、包、替身和符号链接不显示。仅打开系统 Terminal，不拼接或运行命令；运行时复核授权与目录状态。
- **用常用应用打开**：切到“常用应用”页添加本机 `.app`，最多 5 个。默认仅对单选文件显示；确认目标应用支持目录后勾选“所选应用支持文件夹”。不会修改系统默认打开方式。当前已验证文本编辑打开文件、VS Code 打开目录；不保证所有应用接受所有格式。
- 应用升级或移动后先按 bundle ID 定位，再尝试已保存书签；找不到时提示重新添加。来自菜单的请求只引用配置中的应用 ID，不能指定任意程序路径或命令。
- 已保存的目录或应用配置升级后保留。0.4.0 使用 v4 共享配置、v2 动作协议；迁移 v1/v2/v3 配置并读取旧请求。新请求增加可选来源字段区分 Finder、服务和应用内操作。手动关闭全 Finder 覆盖后会持久保存。不支持直接降级到只识别旧配置版本的程序。

## 权限与中断恢复

目录移动后，打开主应用或点击“刷新状态 / 验证目录授权”解析书签并更新覆盖路径；旧菜单快照不会被重定向到新位置。目录不可用时保留设置记录并标记授权失效；全 Finder 模式下菜单仍可见，实际操作会要求重新授权。也可选择该记录并点击“重新授权…”恢复。

新建前保存候选文件路径，写入成功后记录阶段。异常退出后显示中断列表，可“检查目标目录”并在检查后“确认记录”；不会自动重试、删除或覆盖目标。候选路径可能属于原先的同名文件，因此不会仅凭路径存在就推断成功。中断时的部分新文件需人工检查。

启动和每次请求结束时清理历史，也可在“最近验证记录”中手动清理。完成结果保留最近 7 天最多 500 条，同时完整保留近 10 分钟去重标记；超过 1 小时的未提交临时请求清理。未确认中断记录保留，累计 100 条后停止接收新请求并提示检查。阶段日志使用系统管理的 OSLog，不另建无上限日志文件。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `App/` | AppKit 生命周期、独立动作窗口、SwiftUI 设置、目录授权、剪贴板与登录启动 |
| `FinderExtension/` | 动态菜单、按 tag 保存上下文、剪贴板、唤醒同包主应用 |
| `Shared/` | 配置/请求模型、共享容器、待办目录监听与串行处理、路径转义、排他文件创建 |
| `Tests/RightClickCoreTests/` | 命名冲突、并发、路径逃逸、只读目录、请求重放等测试 |
| `Config/` | 主应用/扩展 Info.plist、沙盒 entitlement、签名配置 |
| `scripts/` | 工程生成、签名设置、构建与安装 |
| `docs/` | 各阶段验收报告、已知限制与安装测试矩阵 |

主应用与扩展均开启 App Sandbox；使用相同团队的 App Group 交换目录覆盖配置和请求。目录书签仅保存在主应用的容器中，扩展不会取得完整目录写入授权。没有网络、Apple Events 自动化、完全磁盘访问要求或管理员后台服务。Finder 功能不需要输入监控或辅助功能权限；可选文本历史的全局快捷键需要输入监控，自动粘贴另外需要辅助功能许可。

## 当前行为与限制

- 单选普通目录或其空白处提供新建；单选文件提供复制和适用的打开动作，多选仅提供复制。
- JSON 初始内容为 `{}` 和换行；同名文件增加序号，绝不覆盖原文件。
- 主应用退出后，新建动作会唤醒主应用；Finder 扩展中的复制无需启动主应用，系统服务中的复制由主应用处理。
- 关闭主窗口会隐藏设置并释放其视图；后续新建仅显示独立小窗口。连续提交多个新建请求时每次只处理一个，完成或取消后处理下一项。
- 请求的 URL 是唤醒信号；运行中的主应用同时监听待办目录，启动时先订阅再扫描，避免只依赖一次事件。过期/格式错误请求拒绝后进入终态，不阻塞后续请求。
- 文件创建使用 `openat`、`O_NOFOLLOW`、`O_EXCL`，防止子路径符号链接逃逸与并发同名覆盖。
- 不自动重放已经领取但中途崩溃的请求。主应用提供检查与确认入口；打开外部应用的结果不确定时也不重放。
- “移除”撤销本工具保存的目录授权记录；全 Finder 模式下菜单仍可见，之后操作会再次询问授权。这不是修改系统 TCC 数据库。
- Finder 的普通目录、桌面目录及侧栏支持菜单；网页、其他应用正文、最近使用/搜索结果的空白处没有真实目标目录，不提供通用右键入口。云盘占位文件、网络盘、包内部仍不承诺支持；不会递归扫描目录。
- macOS 26 的 Finder 会把子菜单分隔符显示成整行空白，本版移除这些占位行，采用紧凑连续布局和图标；没有伪造原生灰线或使用私有接口。
- 多行路径输出遇到文件名自身含换行时仍有歧义；请用终端转义路径。这一提示尚未做进菜单界面。
- 已完成请求按保留策略清理；中断请求需要检查后确认。日志不记录路径，创建恢复计划只在本机共享容器中保存候选路径。
- 右键入口采用 Finder Sync，其官方用途主要是同步相关界面扩展；本原型通过实机验证不等于未来系统兼容或 App Store 审核保证。
