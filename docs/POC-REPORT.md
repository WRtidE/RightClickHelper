执行 `swift test`：**8 项测试，0 失败**。它们运行在测试进程中，不能代替真实沙盒和 Finder 验证。

6. POSIX shell 路径转义在空格、引号、美元符号、反引号和换行下可正确还原；特殊字符不被作为命令执行。

## 4. 本轮发现并修复的问题

**菜单显示不代表动作能执行。** 初版将上下文放在 `NSMenuItem.representedObject`，实机菜单可见但复制未生效。修正为整数 `tag` 对应扩展进程内不可变上下文后，单选与多选剪贴板校验通过。保留多份短期快照，避免后打开的菜单改写先前动作目标；不在异步执行时重新查询当前选择。

**同一 bundle ID 可能有多个已注册构建副本。** Xcode 自动注册构建产物，直接复制安装后曾同时存在构建目录和用户 Applications 中的记录。安装脚本现在取消构建副本和旧安装副本的注册；扩展唤醒操作指定同包主应用，降低 URL scheme 误路由到其他副本的风险。

**主应用场景应保持单窗口。** URL 动作可能让原来的 WindowGroup 产生额外窗口；已改用单个 Window 场景，并在最终构建中完成一次 Finder → Markdown 创建复测。

**外部调试读取共享容器会受保护机制影响。** 一次从测试命令直接读取 App Group 诊断文件的尝试没有顺利返回，已终止该读取；后续通过应用自身的“最近验证记录”查看。没有扩大系统权限或关闭保护来获取日志。

## 5. 权限与实现结论

- 目录覆盖列表存于 App Group，主应用保存安全作用域书签；扩展仅提交目标目录与模板请求。
- 创建前由主应用解析书签、开始访问、重新核对目标边界，再通过文件描述符逐级进入目标目录；完成后结束安全作用域访问。
- 用户选择目录后的访问在主应用冷启动后仍有效，证明不是仅依靠一次进程内临时访问。
- 文件名作为数据处理；新建逻辑不调用 shell。`O_EXCL` 保证最终创建时不覆盖已有文件，`O_NOFOLLOW` 防止目标子路径跟随符号链接。
- URL scheme 只传请求 ID；主应用只消费共享容器中有效、限时的结构化请求。不接受外部 URL 中任意路径或命令。
- 已领取但未完成的请求不自动重放；当前是“避免重复执行”的保守恢复策略，不宣称具备完整事务或自动恢复能力。
- 本轮未请求辅助功能、自动化、屏幕录制、完全磁盘访问或管理员权限。UI 自动化测试使用的是测试工具已有的能力，不是原型的运行依赖。
