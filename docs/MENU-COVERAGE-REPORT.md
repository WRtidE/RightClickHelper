# 菜单间距与覆盖范围修复（0.3.1 / build 7）

> 原始证据仅保留在本地，不纳入 Git；本报告保留测试结论与适用范围，详见 [证据说明](./evidence/README.md)。

日期：2026-10-21。环境：macOS 26.5.2 / Apple Silicon。本机开发签名，未公证。

## 问题与改动

此前 Finder 只注册两个已授权测试目录，所以桌面、文稿和下载等位置没有入口。现在默认注册 Finder 的文件系统菜单范围，另保留“仅已授权目录”开关；新增侧栏菜单上下文。这个注册操作不会给主应用或扩展授予整盘读写权限，不枚举文件，也不申请完全磁盘访问。

新建、终端和常用应用请求进入主应用后先检查书签；没有有效授权时，以异步文件夹选择表单请求本次捕获的确切目录。选择其他目录、上级或整个磁盘会拒绝，不会悄悄改变目标。授权成功后继续原请求；取消后完成该请求并释放串行队列。复制路径无需书签。旧授权与常用应用配置保留，v1/v2 配置迁移到 v3。

截图中的大空行来自子菜单中的 `NSMenuItem.separator()`。本版删除三处占位分隔，保持连续紧凑的项目，并给新建、终端和设置添加系统图标。**目前采用无空行布局，尚未实现与 Finder 上一级完全一致的原生灰线。** 没有用文字横线模拟系统分隔符，也不使用私有 API。

## 本轮验证

- 23 项 Swift 自动测试全部通过。新增配置迁移、菜单范围与目录授权独立性、精确授权目标及符号链接拒绝测试。
- 构建、嵌套签名验证通过。最终主应用与扩展均安装为 0.3.1 / build 7，只有一个启用的已安装扩展注册。
- 覆盖更新后原有 3 个目录授权与 2 个常用应用保留。完全退出主应用，从 Finder 发起 Excel 新建，应用冷启动后直接显示创建表单；成功创建“更新后冷启动.xlsx”，未重复询问目录授权。
- 最终配置为 v3、全 Finder 菜单覆盖开启。覆盖限制开关的配置规则通过单元测试，完整 UI 切换回归仍待补测。
- 桌面文件夹空白处、文稿空白处、下载空白处、Finder 侧栏“桌面”均出现右键助手及正确动作。
- 实际桌面背景与菜单显示：用户于 2026-10-21 手动补验并确认“能看到，菜单也正常”。此项记录为用户实测通过，不是自动化验证结果。
- 下载目录“复制完整路径”结果确认为 `~/Downloads`，没有添加该目录授权。
- 新建隔离测试目录 `~/Desktop/右键助手验证-20261021`：第一次点击 Word 出现指向该目录的授权面板；取消后再次点击正常出现授权；授权后继续到文件名表单。
- 连续创建 Word、重复同名 Word、PowerPoint、Excel 成功；重复 Word 自动命名为“菜单覆盖验证 2.docx”。后三次未重复请求目录授权。
- 上述四个 Office 文件通过 ZIP、XML、关系、空白内容、无宏与外部引用校验。这不替代各 Office 版本实际打开验证。
- 紧凑菜单已在 Finder 可访问性树确认动作连续、无空标题项目；自动截图工具没有捕获弹出的菜单窗口，不能用保存的主窗口截图冒充菜单视觉验收。

## 待补验与范围边界

- 实际桌面背景已由用户补验通过。自动化工具对背景点击仍报 `noWindowsAvailable` / `windowNotFoundAtPosition`，后续该入口回归需保留人工验证。
- 网页、其他应用正文和虚拟视图空白处不属于 Finder Sync 的普通目录上下文。
- 外接盘、网络盘、云盘占位文件、系统受保护目录和其他 macOS 版本未在本轮验证，不把菜单注册成功等同于可写。
- 干净账户、系统重启和发行签名公证仍按安装测试矩阵待测。

## 依据与证据

[Apple Finder Sync 指南](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html)说明目录范围、容器/文件/侧栏上下文及仅在菜单调用期间有效的目标 URL。[Apple 开发者论坛 Finder Sync 标签页](https://developer.apple.com/forums/tags/findersync)有同类分隔符被渲染为空行的报告；该报告不是 Apple 官方修复承诺。

本机证据在 `docs/evidence/menu-coverage/`：自动测试、安装记录、Finder 菜单树、首次授权面板、复制路径结果、Office 创建与格式校验。截图若没有实际菜单不会作为视觉通过证据。
