## 开机启动

- 新增“通用”页，使用 `SMAppService.mainApp` 注册与取消登录项；不写 LaunchAgent，不增加管理员组件。
- 开关与说明以系统状态为准，显示未注册、已开启、待批准或不可用状态；失败显示错误，回到应用时刷新，不擅自重启用被系统禁用的项。
- 已实测开启 → 关闭 → 再开启。系统“登录时打开”列表包含 `RightClickHelper.app`，更新安装后仍已开启，最终保持开启。
- 检查启动 Apple Event 的登录项标记，登录启动不主动显示设置。正常启动仍显示设置，Finder/服务请求仍使用独立小窗口。
- 真实注销/重启启动尚未执行；不将注册成功或启动策略单元测试当作真实登录验收。

## 内存修复与空闲检查

- build 17 首轮 300.05 秒空闲采样，两进程 PID 不变，合计单核 CPU **0.163%**。合计 RSS 峰值 **148.09 MiB（155.3 MB）**、结束 **143.03 MiB**；原定 150 MB 峰值目标未达标。
- 连续菜单操作中的 RSS 快照为 **127.72 MiB**；完成创建/冷启动后快照为 **166.16 MiB**。这些是不同阶段快照，不能推导为泄漏曲线。
- build 18 将设置界面改为显式打开时才创建 SwiftUI 视图，关闭时释放视图；Finder/登录启动不预先构建整个设置页。设置状态仍由 AppState 持有。已完成关闭/重开与后台新建实机回归。
- build 18 后台冷启动创建后的初步 RSS 快照为 **150.28 MiB**，低于上述 build 17 创建后快照，但不同运行状态不足以精确归因或证明达到 150 MB 目标。最终 5 分钟结果补充如下。

- build 18 最终连续采样 **300.03 秒**，主应用与自身扩展两个 PID 始终不变；合计单核 CPU **0.033%**，满足 <1% 目标。
- 合计 RSS 起始/峰值 **150.31 MiB（157.6 MB）**，结束 **115.27 MiB（120.9 MB）**。本轮由高到低，未见持续增长；结束值低于 150 MB，但峰值仍超标，不能宣布内存目标全面通过。机器可读结果见 `idle-resources-build18.json`。

短时 RSS 不等同于泄漏分析；当前保留内存目标未达标项。资源采样只统计主应用和自身 Finder 扩展，文本历史保持已启用，未关闭用户其他应用。
